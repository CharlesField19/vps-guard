# VPS Guard

**中文** | [English](README.en.md)

Ubuntu/Debian VPS 的基础检查与管理工具。本文不只列出菜单名称，也说明每项功能解决什么问题、会读取或更改哪些内容，以及使用时应留意什么。只读检查不会更改系统；修改系统的菜单操作通常会先展示目标，并要求输入 `APPLY`。

## 菜单功能详解

### 1. VPS 信息审计（只读）

一次性汇总服务器的基础情况，适合首次接管 VPS、排查问题前收集现状，或把机器状态发给管理员协助判断。报告覆盖发行版/内核、CPU、内存、磁盘空间、SSH 配置、防火墙状态、监听端口、可登录用户、常用服务、Docker 和可用更新等信息。它用于“看清当前状况”，不是自动修复或安全扫描器；输出中的服务、端口或更新信息需要结合用途人工判断。

### 2. SSH / 防火墙

这是 SSH 远程登录配置与 UFW 主机防火墙的入口。两者一起管理，是因为 SSH 端口既要由 SSH 服务监听，也要由防火墙允许；只改其中一侧可能导致无法连接。

- **查看当前状态**：调用 SSH 和网络审计，查看 SSH 配置、端口/网络相关信息，不作更改。
- **SSH 端口与 socket 管理**：同时展示 `sshd` 生效端口、`ssh.socket` 的监听设置和系统实际 TCP 监听，避免把配置文件中的端口误认为已实际生效。设置端口时会先尝试放行新 TCP 端口，并保留 22 端口用于验证；不会自动关闭旧端口。部分发行版由 systemd socket activation（套接字激活）负责监听，因此需要同时处理 `ssh.socket`。请在第二个终端确认新端口能登录后，再决定是否清理旧端口规则。
- **应用 SSH 20001 + 防火墙基础规则**：快捷应用 SSH TCP 端口 `20001`，放行 `20001/80/443`，将 UFW 入站默认策略设为拒绝、出站设为允许，并启用 UFW。适合明确打算采用这套规则的 VPS；不是通用的一键安全配置。若网站或服务使用其他端口，必须另行放行。操作不会自动备份或回滚配置。
- **管理 UFW 端口规则**：可新增 TCP、UDP 或两种协议的端口允许规则，按编号查看并删除规则，也可启用/禁用 UFW、设置入站和出站的默认策略。
  - “入站”是外部连接进入 VPS；默认拒绝通常意味着仅允许明确添加的规则。
  - “出站”是 VPS 主动访问外部；默认拒绝可能阻断 DNS、软件更新、API 调用等连接。
  - 允许某端口只会让防火墙放行流量，不会启动该端口对应的应用。禁用防火墙或默认允许入站可能暴露服务；删除 SSH 规则可能切断当前连接。更改前核对 SSH 端口，并确保有云控制台/救援入口。

### 3. IPv6 状态与配置

先显示系统 IPv6 接口记录、内核的 IPv6 禁用开关和 UFW 的 IPv6 设置。选择启用后，会写入 `/etc/sysctl.d/99-vps-guard-ipv6.conf`，启用本机 IPv6，并在存在 UFW 配置时设置 `IPV6=yes`。这只调整 VPS 本机，不会替云服务商开通 IPv6；还需要服务商分配 IPv6 地址/路由，并正确设置云安全组。看到接口记录也不等于公网 IPv6 已经可达。

### 4. BBR / fq 状态与配置

显示当前 TCP 拥塞控制算法、内核支持的算法列表和默认队列规则。BBR 是 Linux TCP 拥塞控制算法，fq（`fq`）是配合使用的排队规则；它们调整 TCP 发送流量的处理方式，不是带宽扩容或所有网络问题的修复。启用时先确认当前内核报告支持 BBR，然后写入 `/etc/sysctl.d/99-vps-guard-network.conf` 并立即应用。若内核不支持或验证失败，配置不会自动回滚，需要检查提示的配置文件和内核支持情况。

### 5. 软件与内核更新

面向使用 APT 的 Ubuntu/Debian。先用本机已有的软件包索引模拟 `apt-get upgrade`，让你检查哪些包预计更新；模拟阶段不会联网，也不会安装软件。输入 `APPLY` 后才运行 `apt-get update` 刷新软件源索引，再运行 `apt-get upgrade -y` 安装可升级包。它不运行可能移除软件包的 `full-upgrade`，也不会自动重启；内核更新后可能需要在维护时间手动重启。更新期间请保持终端和网络连接。

### 6. 服务管理

列出 SSH、`ssh.socket`、UFW、Fail2Ban、Docker、Nginx、Cron、AppArmor、auditd 等常用 systemd 单元的活动状态，并允许查看详情或执行启动、停止、重启、重载。

- **启动**：启动当前未运行的服务。
- **停止**：中断服务；停止 SSH 可能断开远程管理，停止 UFW 会改变防护状态。
- **重启**：先停止再启动，可能造成短暂中断。
- **重载**：请求服务重新读取配置，通常不中断进程；不支持 reload 的服务会失败。

这不是任意服务浏览器，只列出脚本内预设的常用服务。更改前确认选中的服务名称及影响。

### 7. 监听端口检查

通过 `ss` 查看当前 TCP/UDP 监听项，包括 IPv4/IPv6、绑定地址、端口和进程信息。`127.0.0.1`/`::1` 通常表示仅本机回环访问；绑定 `0.0.0.0`、`[::]` 或通配地址表示监听所有相应地址，可能从公网访问。是否真正可达还取决于 UFW、云安全组、路由和应用认证；此项只展示监听状态，不会更改端口或关闭服务。

### 8. Fail2Ban 管理

Fail2Ban 根据日志中反复出现的失败行为，按 Jail（针对某类服务/日志的监控规则）封禁来源 IP。菜单展示 Jail 与封禁状态，可查看单个 Jail 的状态和封禁 IP、从指定 Jail 解封 IP，或查看 Fail2Ban 日志。解封会让该 IP 再次尝试连接；确认 Jail 和 IP 后再输入 `APPLY`。日志可能包含 IP、用户名等信息。

### 9. 用户与 SSH 密钥

- **列出用户和 sudo 组**：显示具有可登录 shell 的账户及 sudo 组成员，帮助确认哪些账户可能登录或获得管理员权限；不显示密码，也不改账户。
- **创建普通用户**：创建带主目录、默认 Bash shell 的本地用户，可选择加入 sudo 组。加入 sudo 组通常意味着可使用管理员权限。此操作不替用户设置密码；需另行使用 `passwd` 或 SSH 公钥配置登录方式。
- **为用户添加 SSH 公钥**：将输入的单行公钥追加到该用户 `~/.ssh/authorized_keys`，并设置常用目录/文件权限。请确认公钥属于正确的人；追加而非替换现有公钥。
- **启用 root 公钥登录、关闭 root 密码登录**：要求 root 的 `authorized_keys` 已存在，并要求确认已在第二个 SSH 会话中用该密钥成功登录，然后把 `PermitRootLogin` 设为 `prohibit-password` 并尝试重载 SSH。它关闭 root 密码认证，但保留 root 公钥登录。执行前务必保留已验证的会话和控制台救援入口；工具不自动备份或回滚配置。

### 10. 资源监控（只读）

展示系统负载、RAM 使用、各文件系统空间、inode 使用，以及按 CPU 和内存占用排序的前列进程。负载是近期运行/等待任务的平均值，并非 CPU 百分比；磁盘空间充足但 inode 耗尽时也可能无法创建文件。该菜单只提供观察数据，不会结束进程或清理磁盘。

### 11. 日志查看（只读）

从 systemd journal 显示近期记录：SSH/sshd 登录服务日志、Fail2Ban 日志、内核日志中匹配 UFW/BLOCK/DENY 的记录，或错误至紧急级别的服务日志。默认显示最近 80 行，最多 500 行；不写报告文件。日志用于定位登录失败、封禁和服务错误，但记录内容可能包含 IP、用户名或其他敏感信息，不要随意公开完整日志。

### 12. Docker 管理

展示所有 Docker 容器（包括已停止容器）的名称、状态和端口映射，并可对选中的容器执行启动、停止或重启。端口映射表示宿主机端口转发到容器端口；绑定所有地址时可能对公网开放，仍需结合防火墙和应用认证判断。停止/重启会中断应用；此菜单不编辑容器配置、镜像或数据卷。

### 13. 定时任务管理

上半部分只读列出 systemd timers（systemd 的定时单元）；下半部分查看并管理 **root 用户自己的 crontab**，不会编辑其他用户的任务。

- **新增 Cron 任务**：输入完整的一行：5 个时间字段（分钟、小时、日期、月份、星期）加上要运行的命令。例：`0 3 * * 0 /usr/local/sbin/backup.sh` 表示每周日凌晨 3 点运行脚本。工具只做基本行完整性检查，不会验证命令是否正确或时间表达式是否符合预期。root Cron 以管理员权限执行，错误或过于频繁的任务可能造成系统影响。
- **删除 Cron 任务**：按当前列表行号选择并删除 root crontab 中的一行。请核对显示的任务内容，避免删错。

### 14. 安全清理

每类清理都会先显示目标或用量，并要求 `APPLY`。清理不能由本工具自动撤销：

- **APT 缓存**：删除已下载的软件包安装文件，释放空间；不会卸载已安装软件，但以后安装/升级可能需要重新下载。
- **已轮转的 systemd 日志**：将 journal 总量压到你输入的上限（例如 `200M`），旧记录可能被删除，影响历史排障。
- **已停止的 Docker 容器**：列出并删除已退出/已创建但未运行的容器。容器可写层数据会丢失；数据卷和运行中的容器不由此操作删除。
- **悬空 Docker 镜像**：删除未标记且未被容器引用的镜像层，需要时通常可重新拉取或构建。

执行前确认列出的对象确实可以移除，并确保重要数据另有备份。

### 15. 网络安全检查（只读）

显示网卡地址、IPv4/IPv6 路由、DNS 解析配置，并尝试通过外部服务查询公网 IPv4/IPv6 地址。公网 IP 查询需要 VPS 能访问外网；超时可能只是网络限制或服务不可用。该项不改网络配置，也不能读取或修改云平台安全组；要从公网访问服务，还需在云厂商控制台确认安全组/网络 ACL。

### 16. 配置状态导出到终端

把 SSH、网络/UFW 相关审计、Fail2Ban 状态和运行中 Docker 容器的端口/状态连续打印到终端，方便复制用于排障。它不是写入文件的备份或完整系统导出，也不会上传数据；终端输出仍可能包含地址、端口等敏感信息，分享前请检查并打码。

## 运行

在项目目录执行交互菜单：

```bash
sudo bash vps-guard.sh ui
```

命令行审计（可选中文或英文）及建议：

```bash
sudo bash vps-guard.sh audit
sudo bash vps-guard.sh audit en
sudo bash vps-guard.sh plan
```

安装后退出菜单不会删除程序，可直接再次运行：

```bash
sudo bash /opt/vps-guard/vps-guard.sh ui
```

## 安装

```bash
curl -fsSL https://raw.githubusercontent.com/CharlesField19/vps-guard/main/install.sh | sudo bash
```

默认安装到 `/opt/vps-guard` 并打开菜单。再次运行安装命令会覆盖升级现有安装，安装器不会创建安装目录备份。

## 通用注意事项

- 需要 root 权限；目前主要面向 Ubuntu/Debian 和 APT 环境。部分功能需要对应软件/命令已安装（如 UFW、Fail2Ban、Docker、systemd）。
- 先运行信息审计了解当前状态。凡会修改系统状态的操作，确认口令为 `APPLY`；其他输入不会确认操作。
- SSH、防火墙及网络修改可能造成远程失联。操作前确认 VPS 控制台或救援入口可用；更改 SSH 端口后，先从第二个终端测试新端口登录，再手动考虑移除旧端口。
- 脚本不自动备份或回滚配置。更新、清理及账户操作前确认目标和影响；重要数据和配置应自行备份。
- 更新不自动重启；完成后检查系统是否要求重启。
