# VPS Guard

**中文** | [English](README.en.md)

Ubuntu/Debian VPS 的基础检查与管理工具。本文不只列出菜单名称，也说明每项功能解决什么问题、会读取或更改哪些内容，以及使用时应留意什么。只读检查不会更改系统；修改系统的菜单操作通常会先展示目标，并要求输入 `y` 确认或 `n` 取消（不区分大小写）。

## 菜单功能详解

### 1. VPS 信息审计（只读）

一次性汇总服务器的基础情况，适合首次接管 VPS、排查问题前收集现状，或把机器状态发给管理员协助判断。报告覆盖发行版/内核、运行时间、内存、磁盘空间、SSH 配置、防火墙状态、监听端口、用户登录记录、常用服务、Docker 和更新模拟等信息。它用于“看清当前状况”，不是自动修复或安全扫描器；输出中的服务、端口或更新信息需要结合用途人工判断。

对应脚本实际输出包括：

- **系统信息**：发行版名称、内核版本、运行时长、当前执行身份和 UTC 时间。
- **SSH 检查**：`sshd -T` 的有效端口、root 登录、密码/公钥认证、最大认证尝试数、允许用户/组；检查 root 和 `/home/*` 下的 `authorized_keys` 是否存在及其权限。对部分不安全设置给出提示，不自动修复。
- **网络/防火墙检查**：UFW 详细状态；若安装 firewalld，则显示状态和规则；若安装 nft，则列出表摘要；通过 `ss` 展示 TCP/UDP 监听项。
- **服务检查**：显示 Fail2Ban、auditd、AppArmor、UFW、Docker 的 systemd 活动状态，并尝试查询 Fail2Ban 的 `sshd` jail。
- **用户检查**：列出 UID 0 账户、sudo/adm 组成员、最近 15 条成功/失败登录记录，以及近 14 天 SSH 成功认证记录（最多 20 条）。
- **Docker 检查**：显示运行中容器的名称、镜像、端口和状态；对运行中容器打印 privileged、网络/PID 模式和挂载信息，供人工识别高权限配置。
- **资源及基线检查**：显示根文件系统空间、内存、swap，以及若干内核安全参数；检查敏感配置文件权限、是否存在多个 UID 0 账户、是否待重启，并显示登录默认 UMASK。
- **更新预览**：若存在 APT，则运行 `apt-get -s full-upgrade` 并仅显示末尾 8 行。此处是模拟预览，不安装更新；它和主菜单第 5 项的 `apt-get upgrade` 预览/执行范围不同。

### 2. SSH / 防火墙

这是 SSH 远程登录配置与 UFW 主机防火墙的入口。两者一起管理，是因为 SSH 端口既要由 SSH 服务监听，也要由防火墙允许；只改其中一侧可能导致无法连接。

- **查看当前状态**：调用 SSH 和网络审计，查看 SSH 配置、端口/网络相关信息，不作更改。
- **SSH 端口与 socket 管理**：同时展示 `sshd` 生效端口、`ssh.socket` 的监听设置和系统实际 TCP 监听，避免把配置文件中的端口误认为已实际生效。设置端口时会先尝试放行新 TCP 端口，并保留 22 端口用于验证；不会自动关闭旧端口。部分发行版由 systemd socket activation（套接字激活）负责监听，因此需要同时处理 `ssh.socket`。请在第二个终端确认新端口能登录后，再决定是否清理旧端口规则。
- **应用 SSH 20001 + 防火墙基础规则**：快捷应用 SSH TCP 端口 `20001`，放行 `20001/80/443`，将 UFW 入站默认策略设为拒绝、出站设为允许，并启用 UFW。适合明确打算采用这套规则的 VPS；不是通用的一键安全配置。若网站或服务使用其他端口，必须另行放行。操作不会自动备份或回滚配置。
- **管理 UFW 端口规则**：可新增 TCP、UDP 或两种协议的端口允许规则，按编号查看并删除规则，也可启用/禁用 UFW、设置入站和出站的默认策略。
  - “入站”是外部连接进入 VPS；默认拒绝通常意味着仅允许明确添加的规则。
  - “出站”是 VPS 主动访问外部；默认拒绝可能阻断 DNS、软件更新、API 调用等连接。
  - 允许某端口只会让防火墙放行流量，不会启动该端口对应的应用。禁用防火墙或默认允许入站可能暴露服务；删除 SSH 规则可能切断当前连接。更改前核对 SSH 端口，并确保有云控制台/救援入口。

UFW 子菜单编号：1 新增端口规则（再选择 TCP、UDP 或两者）；2 查看编号规则并删除指定编号；3 启用 UFW；4 禁用 UFW；5 默认拒绝入站；6 默认允许入站；7 默认允许出站；8 默认拒绝出站；0 返回。选项 4、6、8 有高风险警告。

SSH 端口子菜单只有两个选项：1 输入 `1-65535` 的新端口，放行新端口并保留 22，然后根据是否启用 `ssh.socket` 写入对应 socket drop-in 或 `sshd_config`，验证配置并重载/重启服务；0 返回。若检测到不是 VPS Guard 管理的 socket drop-in，不会覆盖它。快捷设置不是端口子菜单的一部分，而是 SSH/防火墙主子菜单的选项 3。

### 3. IPv6 状态与配置

先显示系统 IPv6 接口记录、内核的 IPv6 禁用开关和 UFW 的 IPv6 设置。选择启用后，会写入 `/etc/sysctl.d/99-vps-guard-ipv6.conf`，启用本机 IPv6，并在存在 UFW 配置时设置 `IPV6=yes`。这只调整 VPS 本机，不会替云服务商开通 IPv6；还需要服务商分配 IPv6 地址/路由，并正确设置云安全组。看到接口记录也不等于公网 IPv6 已经可达。

该菜单循环显示状态；选项 1 执行启用并要求输入 `y`，选项 0 返回。脚本会用 `sysctl --system` 应用设置，并检查 `net.ipv6.conf.all.disable_ipv6=0`；失败时保留已写入文件，不自动回滚。

### 4. BBR / fq 状态与配置

显示当前 TCP 拥塞控制算法、内核支持的算法列表和默认队列规则。BBR 是 Linux TCP 拥塞控制算法，fq（`fq`）是配合使用的排队规则；它们调整 TCP 发送流量的处理方式，不是带宽扩容或所有网络问题的修复。启用时先确认当前内核报告支持 BBR，然后写入 `/etc/sysctl.d/99-vps-guard-network.conf` 并立即应用。若内核不支持或验证失败，配置不会自动回滚，需要检查提示的配置文件和内核支持情况。

该菜单选项 1 先检查可用算法中是否有 `bbr`，再要求输入 `y`；成功后验证当前拥塞控制为 `bbr`、默认队列为 `fq`。选项 0 返回；不支持 BBR 时不写入配置。

### 5. 软件与内核更新

面向使用 APT 的 Ubuntu/Debian。先用本机已有的软件包索引模拟 `apt-get upgrade`，让你检查哪些包预计更新；模拟阶段不会联网，也不会安装软件。输入 `y` 后才运行 `apt-get update` 刷新软件源索引，再运行 `apt-get upgrade -y` 安装可升级包。它不运行可能移除软件包的 `full-upgrade`，也不会自动重启；内核更新后可能需要在维护时间手动重启。更新期间请保持终端和网络连接。

这里不是循环子菜单：预览后输入 `y` 执行，输入 `n` 或 `0` 返回，其他输入视为取消并返回。系统没有 `apt-get` 或 `apt-cache` 时不会继续。更新成功后若存在 `/var/run/reboot-required`，脚本会提示需要重启。

### 6. 服务管理

列出 SSH、`ssh.socket`、UFW、Fail2Ban、Docker、Nginx、Cron、AppArmor、auditd 等常用 systemd 单元的活动状态，并允许查看详情或执行启动、停止、重启、重载。

列表编号按脚本固定顺序为：1 `ssh`、2 `ssh.socket`、3 `ufw`、4 `fail2ban`、5 `docker`、6 `nginx`、7 `cron`、8 `apparmor`、9 `auditd`。选择服务后先显示最多 12 行 `systemctl status`，再进入动作菜单：1 仅查看状态、2 启动、3 停止、4 重启、5 重载、0 返回服务列表。

- **启动**：启动当前未运行的服务。
- **停止**：中断服务；停止 SSH 可能断开远程管理，停止 UFW 会改变防护状态。
- **重启**：先停止再启动，可能造成短暂中断。
- **重载**：请求服务重新读取配置，通常不中断进程；不支持 reload 的服务会失败。

这不是任意服务浏览器，只列出脚本内预设的常用服务。更改前确认选中的服务名称及影响。

### 7. 监听端口检查

通过 `ss` 查看当前 TCP/UDP 监听项，包括 IPv4/IPv6、绑定地址、端口和进程信息。`127.0.0.1`/`::1` 通常表示仅本机回环访问；绑定 `0.0.0.0`、`[::]` 或通配地址表示监听所有相应地址，可能从公网访问。是否真正可达还取决于 UFW、云安全组、路由和应用认证；此项只展示监听状态，不会更改端口或关闭服务。

### 8. Fail2Ban 管理

Fail2Ban 根据日志中反复出现的失败行为，按 Jail（针对某类服务/日志的监控规则）封禁来源 IP。菜单展示 Jail 与封禁状态，可查看单个 Jail 的状态和封禁 IP、从指定 Jail 解封 IP，或查看 Fail2Ban 日志。解封会让该 IP 再次尝试连接；确认 Jail 和 IP 后输入 `y` 执行，输入 `n` 或其他内容取消。日志可能包含 IP、用户名等信息。

子菜单编号：1 选择 Jail 并显示其状态/封禁 IP；2 选择 Jail、输入 IP 并确认解封；3 显示最近 80 行 Fail2Ban journal；4 安装/确保安装 Fail2Ban 或仅更新已安装版本；0 返回。安装/更新会先执行 `apt-get update`，输入 `y` 确认（不区分大小写），输入 `n` 或其他内容取消，并在完成后尝试启用和启动服务。Fail2Ban 客户端缺失或服务不可连接时，仍可进入菜单并使用选项 4；其他操作会先提示不可用。

### 9. 用户与 SSH 密钥

- **列出用户和 sudo 组**：显示具有可登录 shell 的账户及 sudo 组成员，帮助确认哪些账户可能登录或获得管理员权限；不显示密码，也不改账户。
- **创建普通用户**：创建带主目录、默认 Bash shell 的本地用户，可选择加入 sudo 组。加入 sudo 组通常意味着可使用管理员权限。此操作不替用户设置密码；需另行使用 `passwd` 或 SSH 公钥配置登录方式。
- **为用户添加 SSH 公钥**：将输入的单行公钥追加到该用户 `~/.ssh/authorized_keys`，并设置常用目录/文件权限。请确认公钥属于正确的人；追加而非替换现有公钥。
- **启用 root 公钥登录、关闭 root 密码登录**：要求 root 的 `authorized_keys` 已存在，并要求确认已在第二个 SSH 会话中用该密钥成功登录，然后把 `PermitRootLogin` 设为 `prohibit-password` 并尝试重载 SSH。它关闭 root 密码认证，但保留 root 公钥登录。执行前务必保留已验证的会话和控制台救援入口；工具不自动备份或回滚配置。

子菜单编号：1 列出用户和 sudo 组；2 创建普通用户并选择是否加入 sudo；3 为指定用户追加一行公钥；4 执行 root 密码登录加固；0 返回。

### 10. 资源监控（只读）

展示系统负载、RAM 使用、各文件系统空间、inode 使用，以及按 CPU 和内存占用排序的前列进程。负载是近期运行/等待任务的平均值，并非 CPU 百分比；磁盘空间充足但 inode 耗尽时也可能无法创建文件。该菜单只提供观察数据，不会结束进程或清理磁盘。

### 11. 日志查看（只读）

从 systemd journal 显示近期记录：SSH/sshd 登录服务日志、Fail2Ban 日志、内核日志中匹配 UFW/BLOCK/DENY 的记录，或错误至紧急级别的服务日志。默认显示最近 80 行，最多 500 行；不写报告文件。日志用于定位登录失败、封禁和服务错误，但记录内容可能包含 IP、用户名或其他敏感信息，不要随意公开完整日志。

编号对应：1 SSH 服务日志；2 Fail2Ban 服务日志；3 内核日志中含 UFW/BLOCK/DENY 的记录；4 err 至 alert 优先级的 journal 记录。随后输入行数（默认 80，超过 500 会按 500 显示）；0 返回。

### 12. Docker 管理

展示所有 Docker 容器（包括已停止容器）的名称、状态和端口映射，并可对选中的容器执行启动、停止或重启。端口映射表示宿主机端口转发到容器端口；绑定所有地址时可能对公网开放，仍需结合防火墙和应用认证判断。停止/重启会中断应用；此菜单不编辑容器配置、镜像或数据卷。Docker 不可用时仍可进入此菜单，并通过选项 2 安装/确保安装 Docker，或仅更新已安装的 Docker 软件包。

先显示容器清单；选项 1 进入控制，选择一个容器后再选 1 启动、2 停止、3 重启；选项 2 再选择安装/确保安装或仅更新已安装版本。安装/更新会先执行 `apt-get update`，默认安装 `docker.io`，若软件源提供则同时安装 `docker-compose-plugin`，输入 `y` 确认（不区分大小写），输入 `n` 或其他内容取消，并在完成后尝试启用和启动 Docker 服务。确认容器操作后只操作所选容器；0 返回上一级。

### 13. 定时任务管理

上半部分只读列出 systemd timers（systemd 的定时单元）；下半部分查看并管理 **root 用户自己的 crontab**，不会编辑其他用户的任务。

- **新增 Cron 任务**：输入完整的一行：5 个时间字段（分钟、小时、日期、月份、星期）加上要运行的命令。例：`0 3 * * 0 /usr/local/sbin/backup.sh` 表示每周日凌晨 3 点运行脚本。工具只做基本行完整性检查，不会验证命令是否正确或时间表达式是否符合预期。root Cron 以管理员权限执行，错误或过于频繁的任务可能造成系统影响。
- **删除 Cron 任务**：按当前列表行号选择并删除 root crontab 中的一行。请核对显示的任务内容，避免删错。

菜单编号：1 新增 Cron 行；2 删除所选行；0 返回。systemd timers 部分只有列表输出，不提供启停或编辑操作。

### 14. 安全清理

每类清理都会先显示目标或用量，并要求输入 `y` 确认。输入 `n` 或其他内容取消。清理不能由本工具自动撤销：

- **APT 缓存**：删除已下载的软件包安装文件，释放空间；不会卸载已安装软件，但以后安装/升级可能需要重新下载。
- **已轮转的 systemd 日志**：将 journal 总量压到你输入的上限（例如 `200M`），旧记录可能被删除，影响历史排障。
- **已停止的 Docker 容器**：列出并删除已退出/已创建但未运行的容器。容器可写层数据会丢失；数据卷和运行中的容器不由此操作删除。
- **悬空 Docker 镜像**：删除未标记且未被容器引用的镜像层，需要时通常可重新拉取或构建。

执行前确认列出的对象确实可以移除，并确保重要数据另有备份。

清理子菜单编号就是上述四项；每次完成后按回车回到清理菜单。journal 清理还会要求输入数字加可选单位（如 `200M`、`2G`），并调用 `journalctl --vacuum-size`；Docker 容器/镜像清理会先列出对象，再调用对应的 prune 命令。

### 15. 网络安全检查（只读）

显示网卡地址、IPv4/IPv6 路由、DNS 解析配置，并尝试通过外部服务查询公网 IPv4/IPv6 地址。公网 IP 查询需要 VPS 能访问外网；超时可能只是网络限制或服务不可用。该项不改网络配置，也不能读取或修改云平台安全组；要从公网访问服务，还需在云厂商控制台确认安全组/网络 ACL。

脚本输出顺序为地址、IPv4/IPv6 路由、`resolvectl`（不可用时读取 `/etc/resolv.conf`）、公网 IPv4/IPv6 查询，然后提示检查云安全组；本项没有修改选项。

### 16. 配置状态导出到终端

把 SSH、网络/UFW 相关审计、Fail2Ban 状态和运行中 Docker 容器的端口/状态连续打印到终端，方便复制用于排障。它不是写入文件的备份或完整系统导出，也不会上传数据；终端输出仍可能包含地址、端口等敏感信息，分享前请检查并打码。

## 通用注意事项

- 需要 root 权限；目前主要面向 Ubuntu/Debian 和 APT 环境。部分功能需要对应软件/命令已安装（如 UFW、Fail2Ban、Docker、systemd）。
- 先运行信息审计了解当前状态。凡会修改系统状态的操作，输入 `y`（不区分大小写）确认，输入 `n` 或其他内容取消。
- SSH、防火墙及网络修改可能造成远程失联。操作前确认 VPS 控制台或救援入口可用；更改 SSH 端口后，先从第二个终端测试新端口登录，再手动考虑移除旧端口。
- 脚本不自动备份或回滚配置。更新、清理及账户操作前确认目标和影响；重要数据和配置应自行备份。
- 更新不自动重启；完成后检查系统是否要求重启。
